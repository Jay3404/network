연구 개요서
1. 연구명(안)
Graph- and Burst-Aware Collaborative Prewarming for Latency-Constrained AIoT Serverless Edge Systems
국문
지연 제약 AIoT 서버리스 엣지 시스템을 위한 그래프·버스트 인지형 협업 프리워밍 기법

2. 연구 배경 및 필요성
AIoT 환경에서는 카메라, 센서, 게이트웨이, 산업 단말 등에서 발생하는 이벤트가 시간적으로 몰리며(burstiness), 이를 엣지에서 서버리스 형태로 처리하려는 수요가 커지고 있음. 다만 서버리스 엣지 환경에서는 cold start, 제한된 자원, 엣지 간 네트워크 지연, 함수 간 의존성 때문에 지연이 급격히 커질 수 있음. Azure의 공개 서버리스 trace는 실제 함수 호출 패턴을 제공하고, Alibaba의 microservices trace는 대규모 서비스 의존관계와 응답시간·자원 사용 정보를 제공하므로, 이 둘을 결합하면 버스트 예측 + 네트워크/토폴로지 인지형 협업 프리워밍 연구를 공개 데이터만으로 설계할 수 있음. 
특히 Azure Functions 2019 데이터는 2019년 7월 워크로드 일부를 담고 있으며, 함수 invocation count, 실행시간 분포, 애플리케이션 메모리 분포를 포함. Azure Functions 2021 trace는 2021년 1월 31일부터 2주간의 함수 invocation trace로서 함수 호출 종료시점과 duration을 제공. Alibaba의 2021 microservices trace는 약 2만 개 이상의 마이크로서비스, 1만 개 이상 bare-metal node, 12시간 규모의 운영 데이터를 제공하고, node 자원, microservice resource, call rate/response time, call graph를 포함. 

3. 문제 정의
AIoT 서버리스 엣지 시스템에서 burst한 함수 호출이 발생할 때,
어떤 함수 컨테이너를, 어느 엣지 노드에, 언제, 얼마나 미리 띄워야
지연을 최소화하면서 자원 낭비를 줄일 수 있는가?
기존 프리워밍 연구는 대체로 단일 노드 또는 단순 workload 예측에 집중하는 경우가 많음. 그러나 실제 AIoT/edge 환경에서는 인접 노드 공유 가능성, 서비스 호출 그래프, 네트워크 hop/latency, 노드별 자원 혼잡도를 함께 고려해야 함. 본 연구는 burst-aware + graph-aware + neighbor-collaborative + placement-aware의 통합 프레임을 제안함을 목표로 수립. 

4. 연구 목표
1.	AIoT 서버리스 엣지 환경의 burst 패턴을 예측하는 경량 모델을 설계. 
2.	서비스 의존 그래프와 엣지 토폴로지를 반영한 협업 프리워밍 정책을 설계. 
3.	컨테이너 placement와 prewarming 결정을 동시에 고려하는 알고리즘을 제안. 
4.	공개 trace 기반 시뮬레이션으로 p95 latency, cold-start rate, SLO violation, resource cost 측면에서 기존 기법 대비 우수성을 입증. 

5. 핵심 연구 질문
•	함수 호출 burst를 미리 예측하면 cold start와 tail latency를 얼마나 줄일 수 있는가? 
•	인접 엣지 노드 간 컨테이너 공유를 허용하면 local-only warming 대비 어떤 이득이 있는가? 
•	서비스 call graph와 node 자원 상태를 함께 고려한 placement가 단순 휴리스틱보다 효과적인가? 
•	예측 오차가 존재하더라도 협업 프리워밍 정책은 안정적으로 동작하는가? 
•	latency 개선 대비 추가 resource overhead는 수용 가능한 수준인가? 

6. 제안 방법 개요
전체 프레임워크
본 연구는 크게 3개 모듈로 구성됩니다.
(1) Burst Predictor
Azure trace를 이용해 application/function 단위의 invocation burst를 예측. 초기 버전은 빠른 재현을 위해 TCN, LSTM, LightGBM 기반 rolling forecast로 시작하고, 필요 시 Transformer 계열로 확장. Azure 2019는 per-minute invocation count와 실행시간/메모리 분포를 제공하고, Azure 2021은 per-invocation 시계열을 제공하므로 두 trace를 상보적으로 활용할 수 있음. 
(2) Graph-Aware Collaborative Prewarming
Alibaba microservices trace의 call graph, response time, node/resource 정보를 이용해 서비스 간 연관도와 resource affinity를 추정하고, 이를 엣지 환경의 함수 의존성 priors로 사용합니다. 즉, 자주 함께 호출되는 함수 또는 연쇄적으로 이어지는 함수는 동일 노드 혹은 인접 노드에 사전 배치하도록 설계. 
(3) Joint Placement & Warming Policy
예측된 burst, 서비스 그래프, 노드 자원 상태를 함께 입력으로 받아
•	어느 노드에 warm instance를 둘지 
•	몇 개를 유지할지 
•	어느 시점에 scale out/in 할지
를 결정합니다.
초기 논문 버전은 경량 휴리스틱 + graph score + resource score 방식으로 구현하고, 후속 확장으로 RL/GNN 기반 policy를 붙이는 것이 현실적. EdgeCloudSim은 computation과 networking 자원을 함께 고려하는 edge simulation 환경이고, faas-sim은 trace-driven FaaS simulation을 지원하므로, 두 도구를 조합하면 빠른 프로토타이핑이 가능. 

7. 데이터셋 및 출처
데이터셋 1: Azure Functions Trace 2019
•	Microsoft Azure Functions의 2019년 7월 공개 workload 일부 
•	함수 invocation count, trigger type, 실행시간 분포, 애플리케이션 메모리 분포 포함 
•	application-level burstiness와 workload statistics 학습에 적합 
데이터셋 2: Azure Functions Invocation Trace 2021
•	2021년 1월 31일부터 2주간의 함수 invocation trace 
•	app, func, end_timestamp, duration 제공 
•	function-level arrival dynamics와 burst timing 분석에 적합 
•	다만 공식 GitHub 이슈 기준으로 duration은 cold start 시간을 포함하지 않는 것으로 안내되어 있어, cold start penalty는 시뮬레이터에서 별도로 모델링하는 것이 적절 
데이터셋 3: Alibaba Cluster Trace Microservices v2021
•	2021년 12시간 규모, 약 2만 개 이상의 microservices, 1만 개 이상의 bare-metal node 기반 
•	node runtime 정보, microservice resource 정보, call rate/response time 정보, sampled call graph 제공 
•	서비스 의존성, 노드 자원 상태, network-aware placement priors 구성에 적합 
시뮬레이터 1: EdgeCloudSim
•	computation과 networking resource를 함께 고려하는 edge computing simulator 
•	edge node topology, latency, mobility/placement 수준의 실험 확장에 적합 
시뮬레이터 2: faas-sim
•	trace-driven serverless/FaaS simulator 
•	scheduling, autoscaling, load balancing, placement 전략 평가 가능

9. 실험 설계
입력 구성
•	Workload stream: Azure 2019 + Azure 2021 기반 invocation dynamics 
•	Service dependency prior: Alibaba call graph / response-time structure 
•	Node resource state: Alibaba node + MS resource metrics 
•	Network topology: EdgeCloudSim/faaS-sim에서 edge-node graph 설정 
비교 baseline
1.	Reactive scaling only 
2.	Static prewarming 
3.	Local-only predictive warming 
4.	Neighbor-aware warming (shared warm pool) 
5.	제안 기법: graph- and burst-aware collaborative prewarming 
평가 지표
•	Average latency 
•	p95 / p99 latency 
•	Cold-start rate 
•	SLO violation rate 
•	Resource cost (warm instance hours / memory overhead) 
•	Network overhead (cross-edge redirection / traffic) 
•	Energy proxy 또는 utilization efficiency 
Ablation
•	burst prediction 제거 
•	graph prior 제거 
•	neighbor sharing 제거 
•	placement optimization 제거 
•	cold-start penalty 민감도 분석 
•	topology density 변화 실험 

10. 예상 기여
기여 1.
AIoT 서버리스 엣지 환경에서 burst prediction과 graph-aware collaboration을 결합한 프리워밍 프레임워크를 제안. 
기여 2.
공개된 Azure serverless trace + Alibaba microservices trace를 함께 활용하여, 실제 운영 패턴을 반영한 edge/serverless benchmark 시나리오를 구축. 
기여 3.
단순 prewarming이 아니라 node placement와 warm-instance allocation의 결합 문제로 정식화하여, 네트워크 지연과 자원 효율을 동시에 고려. 
기여 4.
tail latency, cold-start reduction, resource overhead 측면에서 기존 heuristic 대비 실질적 개선을 제시. 이는 FGCS급 저널에서 선호하는 시스템적 기여 포맷과도 잘 맞음. 이 방향성은 송 교수님 최근 serverless edge 및 IoT 네트워크 실적과도 연결 가능. 

11. 예상 한계 및 대응
한계 1
Azure trace는 실제 edge 토폴로지를 직접 제공하지 않음.
→ 대응: EdgeCloudSim/faaS-sim에서 edge graph를 설계하고, Alibaba trace의 node/resource/call graph 정보를 사용해 realistic prior를 부여. 
한계 2
Azure 2021 duration에는 cold start가 직접 포함되지 않음.
→ 대응: cold start penalty를 simulator parameter로 외생적으로 모델링하고 민감도 분석을 수행. 
한계 3
Alibaba microservice trace는 edge-native FaaS 데이터가 아니라 cloud production trace.
→ 대응: service dependency와 resource coupling prior를 추출하는 용도로 사용하고, 실제 FaaS invocation stream은 Azure trace에서 공급하는 hybrid benchmark 형태로 설계.
